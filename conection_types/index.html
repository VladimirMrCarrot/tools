УспадкуванняInheritance generalizationgeneralization

ЗмістMeaning

Не знаєте, який звʼязок? Чотири питання по черзіNot sure which one? Four questions in order

  1. A є різновидом B? Так: успадкування. Якщо B лише контракт без власної реалізації (інтерфейс): реалізація.Is A a kind of B? Yes: inheritance. If B is only a contract with no implementation of its own (an interface): realization.
  2. A є частиною B? Так, і без B частина зникає та належить лише йому: композиція. Так, але частина живе сама і може бути в іншому цілому: агрегація.Is A a part of B? Yes, and the part vanishes without B and belongs to it alone: composition. Yes, but the part lives on its own and may sit in another whole: aggregation.
  3. A довго зберігає посилання на B (поле, атрибут, FK)? Так: асоціація, додайте кратність.Does A keep a lasting reference to B (field, attribute, FK)? Yes: association, add multiplicity.
  4. A потребує B лише на час дії (параметр, локальна змінна, виклик)? Так: залежність. Ні: на діаграмі класів звʼязку немає.Does A need B only during an action (parameter, local variable, call)? Yes: dependency. No: no line on the class diagram.

Клас чи обʼєкт? Усі шість звʼязків малюють між класами (діаграма класів). «Дуб» тут клас, а конкретний дуб у парку це обʼєкт, його звʼязок із класом називають instance-of і на діаграмі класів не показують. Class or object? All six relationships are drawn between classes (class diagram). Oak here is a class; a specific oak in a park is an object, its link to the class is instance-of and is not shown on a class diagram.

Кратність і напрямокMultiplicity and direction

Кратність пишуть біля кінця лінії і читають «з протилежного кінця»: число біля «Гриба» каже, скільки грибів має одне дерево. Multiplicity sits at a line end and is read “from the other end”: the number next to Mushroom says how many mushrooms one tree has.

А як це виглядає в базі данихWhat this looks like in a database

UML описує класи, таблиці описують дані. Відповідність не один-до-одного, але для аналітика корисна: звʼязок на діаграмі підказує, де лежить зовнішній ключ і що робити при видаленні. UML describes classes, tables describe data. The mapping is not one-to-one, but it helps an analyst: the relationship on the diagram hints where the foreign key lives and what happens on delete.

Асоціація 1 — 0..1Association 1 — 0..1FK з unique на боці 0..1 або спільний PKFK with unique on the 0..1 side, or a shared PK
Асоціація * — *Association * — *проміжна таблиця з двома FK і складеним PKa join table with two FKs and a composite PK
КомпозиціяCompositionFK not null + on delete cascade: частина зникає з цілимFK not null + on delete cascade: the part goes with the whole

  , order_id  bigint not null references orders (id) on delete cascade
  , qty       int    not null
)
;

create table nest (
    id        bigint not null primary key
  , tree_id   bigint null     references tree (id)   on delete set null
)
;

create table tree_mushroom (

  , mushroom_id  bigint not null references mushroom (id)
  , primary key (tree_id, mushroom_id)
)
;
